## 物理端口

| 端口 | 接线 | 路由器处理方式 |
| --- | --- | --- |
| LAN5 | 光猫 IPTV 输出口 → 路由器 LAN5 | 作为路由器侧 IPTV 输入口，使用 `lan5.85` 接收光猫输出的 VLAN 85 标签数据 |
| LAN4 | 中兴机顶盒 | 未打标签帧进入隔离的 `br-stb`；VLAN 85 标签帧通过 `lan4.85` 透明桥接到 LAN5 |

IPTV 数据方向是“光猫 IPTV 输出口 → 路由器 LAN5 输入 → `lan5.85` → `br-iptv`”。`br-iptv` 随后分别向 udpxy 和 LAN4 的 `lan4.85` 提供 IPTV 数据。

2026-11-14 最后检查时，LAN5、`lan5.85` 和 `br-iptv` 均为 UP；LAN4 为 `NO-CARRIER`，因此本次只能确认历史机顶盒租约，不能重新确认机顶盒的物理播放状态。

中兴机顶盒同时使用两套网络：本地未打标签 DHCP 服务提供 Option 125 和普通互联网访问；VLAN 85 提供运营商 IPTV 专网。不要删除 LAN4 混合端口配置中的任何一侧。

- `br-iptv`：由 `lan5.85` 和 `lan4.85` 组成的网桥。
- `iptv_probe`：在 `br-iptv` 上使用 DHCP，但不接管默认路由和上游 DNS；已观察到地址 `30.171.109.55/16`，DHCP 网关为 `30.171.0.1`。
- IPTV 路由 `30.171.0.0/16` 直连 `br-iptv`，DHCP 还下发了经 `30.171.0.1` 到 `124.75.22.247/32` 的主机路由；默认路由仍然走普通 WAN。
- `br-stb`：只包含未打标签的 LAN4，地址为 `192.168.32.1/24`，DHCP 范围为 `.2-.21`。
- DHCP Option 125 使用用户旧配置中记录的上海电信中兴机顶盒参数。
- 防火墙将机顶盒网段放在独立区域中，允许机顶盒访问 WAN；未配置机顶盒到主 LAN 的转发。
- `igmpproxy` 将组播从 `br-iptv` 路由到隔离的 `br-stb`；同时保留 `lan5.85` 到 `lan4.85` 的 VLAN 85 二层透明桥接。当前尚未通过停机对照测试确定机顶盒是否只需其中一条路径。

- 自定义 `/etc/init.d/udpxy` 支持套接字缓冲参数；sysctl 设置为 `rmem_max=8388608`。
- `/etc/init.d/udpxy` 和 `/etc/sysctl.d/90-udpxy-buffer.conf` 已加入 `sysupgrade` 备份清单。

## EPG 限制

当前 EPG 来源是公共地址 `https://epg.pw/xmltv/epg_CN.xml.gz`，在本地筛选并按名称匹配。它不是中兴机顶盒使用的上海电信原生 EPG。目前有 12 个频道没有匹配，详见在线 EPG 的 `status.json` 接口。100 条匹配记录对应 89 个唯一上游节目单，其中 11 个 4K 同播频道复用同名普通频道的节目安排。频道名称、覆盖范围和上游可用性都可能变化。

此前调研过的项目可以抓取上海电信原生频道列表和 EPG，但它需要 IPTV 用户 ID、机顶盒 SN、MAC，以及运营商专网访问能力。目前尚未获取并验证 SN，也没有部署原生抓取程序；NAS 容器当前也没有被路由到 IPTV VLAN。禁止将账号、SN 或令牌写入 Git。
